# 2026.327.0211 — fix(arch)!: the Arch package pin moves to the release the repo now serves

## Summary

`2026.279.2144` is no longer served by the `charly-arch` repository — the 2026-11-23 republish replaced the published set — so any image on an Arch-family base fails at the charly install step. Measured on `charly distro-cachyos`'s `charly-selftest`, which is this repo's Arch-family witness:

```
#26 1.893 error: target not found: charly=2026.279.2144
#26 ERROR: process "… pacman -Syu --noconfirm --needed charly=2026.279.2144" did not complete successfully: exit code: 1
```

The Arch pin moves to **`2026.326.1922`**, whose current pkgrel is `-2`. That release was rebuilt by the packaging plugin carrying opencharly/sdk#397's rule — no mutual `Replaces` in the variant family — so a routine `pacman -Syu` resolves instead of refusing (opencharly/layer-charly#23). The metadata, fetched from the served repo:

```
== charly          Version: 2026.326.1922-2  Provides: charly  Conflicts With: charly-full charly-minimal  Replaces: None
== charly-full     Version: 2026.326.1922-2  Provides: charly  Conflicts With: charly charly-minimal       Replaces: None
== charly-minimal  Version: 2026.326.1922-2  Provides: charly  Conflicts With: charly charly-full            Replaces: None
```

`Replaces: None` on all three is the property the conflict needed. pacman picks the highest pkgrel for a version, so the pin names the version only.

The debian/ubuntu/alpine pins are untouched: their registries were not republished by this fix, and the change does not pretend otherwise.
