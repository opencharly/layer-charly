### Why

On Ubuntu 26.04 (resolute) installing the virtualization stack writes a fatal into the package log:

```
Setting up libvirt-daemon-system (12.0.0-1ubuntu5.6) ...
Creating group 'libvirt-qemu' with GID 64055.
Creating user 'libvirt-qemu' (libvirt QEMU user) with UID 64055 and GID 64055.
fatal: The group `libvirt' does not exist.
```

The maintainer script adds `libvirt-qemu` to the `libvirt` group **before it creates that group**. The install
exits 0 and the group exists moments later, but a `disposable: true` VM bed's `deploy-add` gate rightly refuses
to ignore a `fatal:` line — so a 26.04 VM bed cannot pass.

Measured both ways in a disposable `ubuntu:26.04`: reordering the packages only **moves** the message;
**pre-creating the group gives 0 fatal lines**. #8 adds exactly that, ordered ahead of `virtualization` through
`require:` — a plan step inside `virtualization` would run too late, because charly emits a candy's declarative
packages as a `RUN apt-get install` before any `plan:` step.

This repo is the link that carries it: `layer-charly` pins `pod-virtualization` directly, and the consumer VM
beds pin `layer-charly`.
