# 2026.321.0800 — fix(charly)!: re-declare the charly repo in the ubuntu-26.04 section — repo lists override, not union

## Summary

Re-declares **both** apt repos in the `ubuntu-26.04:` section of the `charly` candy's `distro:` map. The
previous change (#21) added that section with only the tailscale repo, on the premise that "only the repo
override is needed" — which broke 26.04 outright.

Head `2a3c0c3`, **1 file, 13 insertions(+), 2 deletions(-)**.

### The mechanism — repos OVERRIDE, packages union

```
PACKAGES  union with the generic `ubuntu:` section   -> the 26.04 section needs only what differs
REPO      lists OVERRIDE — most specific wins        -> the 26.04 section must re-declare ALL of them
```

The generic `ubuntu:` section declares two repos (`charly`, `tailscale`). My new section declared one, so a
26.04 image lost the `charly` repo and the guest could not install the toolchain the image exists to provide:

```
Reading state information...
E: Unable to locate package charly
plugin-deploy-vm: walk step "SystemPackages" …
```

Measured on `opencharly/distro-ubuntu#65`'s VM bed, run `2026.321.0749`, `[deploy-add] FAIL after 32.284s`.

### Why it got through

`#21`'s validator asked exactly this question — union or override? — on a **sibling** repo
(opencharly/layer-container-nesting#18), and I answered it there by proving that **packages** union. I never
asked it again for **repos** in this repo, where the generic section carries a *second* repo the override
silently drops. Same question, one field over.
