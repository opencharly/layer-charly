# 2026.328.0806 — fix(pins): move the pixi builder to the release that pins HOME/PIXI_HOME

## Summary

`charly.yml` pins the four external builder plugins as the BUILDER REPLY CONTRACT, and its own
comment states the rule they follow: *"Bump them WITH the binary's own pins, never after."* npm,
cargo and aur already agree with `charly/charly.yml`; **pixi did not** — it still named
`v2026.326.2258`, one release behind the binary's `v2026.327.1705`.

That release emits a pixi stage with neither `HOME` nor `PIXI_HOME` set. `$PIXI_HOME` defaults to
`$HOME/.pixi`, so without `HOME` the environment lands outside the box home: every image built
through this layer got a pixi env that no `<home>/.pixi` check could find, while the build stayed
green. `v2026.327.1705` carries the fix (opencharly/sdk#627, opencharly/plugin-builder-pixi#10).

| File | Change |
|---|---|
| `charly.yml` | `plugin-builder-pixi` `v2026.326.2258` → `v2026.327.1705`, plus the comment naming what the old release got wrong |
