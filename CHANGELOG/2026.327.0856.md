# 2026.327.0856 — fix(pins)!: the charly layer vendors the builder plugins at the reply contract, not at v2026.271

## Summary

The four detection-builder plugin refs in this candy were pinned at `v2026.271.*` — from **before** the builder reply contract (`opencharly/sdk#615`, `opencharly/sdk#608`). The pins are load-bearing: the connect path's pass-1 vendors each plugin **by word** from the project's own candy closure, so a pre-contract pin here makes every builder-using image in a project that composes this candy fail to **render**.

This moves the four to the versions `charly/charly.yml` ships — `pixi v2026.326.2258`, `npm v2026.327.0024`, `cargo v2026.326.2259`, `aur v2026.327.0012` — and states the rule beside them so the next bump travels with the binary's own. One file, four refs, plus the comment that explains why they matter.
